# 09. Анализ повторных покупок

**Бизнес-задача:** Через какое время покупатели возвращаются и как меняются интервалы между покупками и средний чек?

Решение тестового задания: последовательность заказов клиента, время между покупками, пузырьковая диаграмма и SQL по скидкам менеджеров из Парижа. Данные: 5 009 заказов и 793 клиента за 2015–2018 годы.

## Открыть готовую работу

- **[Report.html](Report.html)** — интерактивный отчёт. Скачайте файл и откройте браузером; работает без интернета. GitHub показывает исходный HTML, поэтому используйте Download raw file.
- **[Конспект в Word](Конспект.docx)** и **[конспект на GitHub](Конспект.md)** — пошаговый разбор, формулы, выводы, ограничения и ответы для собеседования.
- **[paris_discounts.sql](paris_discounts.sql)** — ответ на SQL-часть, диалект SQLite 3.
- **[solution.zip](solution.zip)** — полный воспроизводимый проект с данными, исходным кодом, SQL, конспектом и проверками. Распакуйте архив с сохранением папок.

В локальном полном проекте документы находятся в docs, запросы — в sql. При публикации ключевые файлы продублированы в корень для удобства просмотра. Для запуска кода используйте структуру из solution.zip.

## Что показал анализ

От второй к десятой покупке средний интервал снижается с 279,03 до 83,06 дня, но число наблюдений уменьшается с 781 до 88. Средний чек не растёт последовательно: 439,66 у вторых, 548,54 у четвёртых и 339,41 у десятых покупок. У покупок с номером 14–17 по одному наблюдению.

Это описание доступной истории, а не доказательство роста лояльности. На результат влияют состав клиентов и ограниченный период наблюдения. Первая покупка означает первую в файле; её интервал пустой. Для заказов одной даты порядок задан Order ID, поскольку времени покупки нет. Номера рассчитаны до фильтров.

## SQL и допущения

Фактических данных Orders, Clients, Loyalty и Managers в задании нет. Запрос проверен на синтетических сценариях. Предполагается, что Orders.sum — сумма строки до скидки; скидка = sum × discount, без повторного умножения на quantity. Выводятся все годы, присутствующие в Orders, в том числе нули для менеджера без продаж. Неизвестный статус даёт NULL и счётчик проблемных строк. Историческая скидка требует ставки в заказе или истории статусов; данная схема содержит только текущий Loyalty.

Исходный Excel и документы задания в публикацию не включены. Для воспроизведения оставлены идентификаторы и необходимые поля; имена клиентов и адреса исключены. Готовый BI-отчёт поставляется в HTML; нативного PBIX в комплекте нет.
